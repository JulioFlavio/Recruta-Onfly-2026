  Falhas por teste

  1. test_currency_conversion_to_brl: esperado 642.00, obtido 118.45

  - Causa: currency_converter.py:11
    (src/onfly_report/services/currency_converter.py#L11) faz float(amount) /
    float(rate). Divide em vez de multiplicar (100 / 5.42 = 18.45; somado aos
    100 BRL dá 118.45) e ainda passa por float, o que o README proíbe para
    dinheiro.
  - Solução: return amount * rates[currency], tudo em Decimal.

  2. test_nights_across_month_boundary: esperado 3, obtido -28

  - Causa: stay_calculator.py:10
    (src/onfly_report/services/stay_calculator.py#L10) subtrai só o dia do mês
    (checkout.day - checkin.day, ou seja, 2 − 30 = −28). Quebra em qualquer
    virada de mês ou ano.
  - Solução: (checkout - checkin).days * rooms.

  3. test_status_rules_exclude_cancelled_and_no_show: esperado 100.00, obtido
  120.00

  - Causa: status_policy.py:8 (src/onfly_report/services/status_policy.py#L8)
    usa status != "CANCELLED", então NO_SHOW (os 20.00) entra como faturável.
  - Solução: return status == "CONFIRMED". Uma lista de permissões é mais segura
    do que uma de exclusões.

  4. test_top_hotels_are_ranked_descending: esperado H01, H02, H03, obtido H04,
  H03, H02

  - Causa: report_builder.py:91
    (src/onfly_report/services/report_builder.py#L91) ordena por (amount,
    hotel_id) em ordem crescente, quando o ranking deveria ser decrescente.
  - Solução: key=lambda item: (-item[1]["amount"], item[0]). Isso deixa o valor
    decrescente e o desempate por hotel_id crescente, como o README pede. Usar
    reverse=True erraria o desempate.

  5. test_regression_report_on_sample: total_amount_brl saiu 1018.45 (esperado
  1542.00) e average_nightly_rate_brl saiu 203.69 (esperado 308.40)

  - Causa: é o mesmo defeito de câmbio do item 1. As contagens e as noites já
    batem neste teste porque ele não tem NO_SHOW nem virada de mês.
  - Solução: a mesma do item 1. Depois dela, a média fica 1542 / 5 = 308.40.

● Ela não é chamada em nenhum lugar do código, e isso é proposital: quem chama é
  o pytest. (O nome completo é test_regression_report_on_sample.) A busca
  confirma que o nome só aparece na própria definição, em
  test_regression_report.py:6 (tests/test_regression_report.py#L6).

  Quando você roda pytest -q, acontece o seguinte:

  1. O pytest lê o pyproject.toml, onde testpaths = ["tests"] diz em qual pasta
     procurar.
  2. Lá dentro ele carrega os arquivos cujo nome segue o padrão test_*.py. É o
     caso de test_regression_report.py.
  3. Em cada arquivo, ele executa as funções cujo nome começa com test. É o caso
     de test_regression_report_on_sample.
  4. A função pede um parâmetro tmp_path, e o pytest o fornece automaticamente.
     É uma fixture nativa que cria uma pasta temporária para cada teste.

  Dentro do teste, quem faz o trabalho é run_cli, de helpers.py:52
  (tests/helpers.py#L52). Ela grava um CSV temporário e executa o CLI de verdade
  num subprocesso (python -m onfly_report ...). Depois lê o JSON gerado, que é
  onde as asserções atuam.

  Para rodar só esse teste:

  .venv/Scripts/python -m pytest
  tests/test_regression_report.py::test_regression_report_on_sample -v
